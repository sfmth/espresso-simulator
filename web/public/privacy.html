Privacy and browser storage

Puckworks runs simulations on your device. There are no accounts, analytics, advertising or telemetry. The app does not upload your recipes, imported files, journal, ratings or calibration.

What stays in this browser

On your first visit, open Set up equipment or explicitly skip with defaults. Equipment setup, known constraints, recorded setup shots, alternative configurations and valid recipe drafts are saved in local browser storage. Use Set up equipment to review them later and export a separate equipment backup. The cookie described below contains no equipment details, recipe values or personal identifier.

Saved journal records, observations, ratings and calibration use the browser’s local database. Imports are parsed locally. Downloads and backups leave the app only when you export a file. Current editor inputs and running simulations can reset when you reload, so export a recipe or backup before updating if you want to keep them.

Browser storage can be cleared or evicted, and private browsing may remove it when the session closes. Keep a journal backup somewhere you control; browser storage is not a backup.

Setup cookie

One first-party cookie, puckworks_setup_v1=done, remembers that setup has completed for up to one year. It is limited to this app's path, uses SameSite=Strict, and uses Secure on HTTPS. It has the same fixed value for every user and contains no machine, grinder, recipe, journal or tracking identifier.

Browsers automatically include this completion marker in matching requests to the host. Equipment settings remain in local browser storage. If cookies are blocked, saved local setup can still be restored. If all storage is blocked, setup works for the current session and will be requested again on a later visit. You can remove the cookie and saved setup through your browser's site-data controls.

Downloaded app files

On supported browsers, Puckworks downloads its own app files, presets and simulation engine for offline use. Wait for Ready for offline use before disconnecting. A first visit needs a connection, and a browser may require a reload to enable its saved copy. Installation on your home screen is optional and depends on your browser.

Updates download in the background. An available update waits until you choose Reload to update; the app does not reload a running simulation automatically. Older app downloads can stay while another tab still needs them.

Downloaded app files use a separate cache from your journal. Removing only those cached files does not delete journal records. Clearing all site data can delete both: export a journal backup first. Closing every Puckworks tab lets a subsequent update discard unused older app copies.

Connections and hosting

The app and its workers request only files from this site’s own origin. Fonts, libraries and model files are bundled locally. Links you choose to open, such as source code and research references, go to their named sites.

The public site is hosted on GitHub Pages. GitHub may process normal hosting access logs, including connection information such as IP addresses, under its own privacy terms. Those hosting logs are outside Puckworks; the app has no access to them and does not use them to learn from your shots.

Exports can contain recipes, observations, ratings and calibration records. Anyone you give an exported file to can read the information it contains.
